# UContent Roadmap

UContent должен вырасти из набора удобных скриптов в полноценную операционную систему для авторской редакции: место, где сценарий, фактура, медиа, монтажные решения, публикация и архив живут в одном непрерывном процессе.

Главная цель: один человек или маленькая команда должны делать выпуск быстрее, спокойнее и качественнее, чем большая редакция с россыпью разрозненных инструментов.

## Product North Star

UContent - это редакционный центр управления выпуском.

Он должен:

- находить и сохранять материалы из ссылок, соцсетей, сайтов, RSS и Telegram;
- понимать, что именно скачано: источник, автор, описание, качество, права, дата, контекст;
- связывать каждый медиафайл с конкретным местом сценария;
- помогать выбирать лучший фрагмент, кадр, цитату, таймкод и подпись;
- превращать сырой хаос источников в аккуратную медиатеку;
- собирать выпусковые материалы для монтажа без ручного перекладывания файлов;
- оставаться локальным, переносимым и контролируемым владельцем проекта.

## Product Principles

- Local first: рабочая копия, медиа, индексы и история должны быть доступны без облачной зависимости.
- Source aware: любой файл должен помнить, откуда он пришел, кто автор, какое описание было у оригинала и когда он был получен.
- Editor speed: частые действия должны занимать один тап или одну клавишу.
- Trust over magic: если инструмент не уверен, он должен показывать причину, а не притворяться, что все хорошо.
- Recoverability: не терять файлы, не перетирать данные, иметь историю действий и возможность отката.
- Quiet interface: UI должен помогать работать часами, не превращаясь в ярмарку кнопок.
- Boring reliability: загрузка, перемещение, переименование, индексация и отправка в Telegram должны быть предсказуемыми.
- Human taste remains central: автоматизация предлагает, человек утверждает.

## Phase 1 - Stabilize The Core

Цель: текущий Telegram + web workflow должен стать надежной ежедневной системой.

- Media download pipeline:
  - единая модель результата для `yt-dlp`, `gallery-dl`, direct download и fallback;
  - сравнение качества дубликатов для X/Twitter, TikTok, Instagram и других соцсетей;
  - сохранение metadata sidecar и нормализация `title`, `description`, `uploader`, `webpage_url`;
  - понятные ошибки: блокировка, DNS, cookies, file too large, extractor broken, no media;
  - встроенная диагностика загрузчиков в админке.

- Telegram workflow:
  - подписи всегда показывают источник, автора, качество, размер и папку, если файл точно там лежит;
  - inline-кнопки не ломаются при редактировании сообщений и media group;
  - выбор папки сортируется по недавним изменениям;
  - создание папки, перемещение, переименование и нарезка подтверждаются фактическим состоянием файла;
  - аккуратная очередь загрузок с видимым статусом и retry.

- Media library:
  - единый `media-index.json` как источник истины;
  - проверка битых ссылок индекса на дисковые файлы;
  - repair-команда для восстановления индекса по папке `media/`;
  - поиск по автору, источнику, описанию, теме, размеру и дате;
  - быстрые фильтры: unsorted, recently added, missing metadata, duplicates, large files.

- Verification:
  - smoke tests для download -> publish -> send -> move;
  - fixture-тесты для TikTok, X/Twitter, YouTube, Instagram, прямых MP4;
  - обязательный encoding check для русских текстов;
  - отдельный тест контейнерных video-команд на реальном медиафайле.

## Phase 2 - Editorial Workspace

Цель: сценарий и медиа должны ощущаться как единый рабочий стол.

- Segment workspace:
  - каждый абзац/сегмент сценария видит свои источники, медиа, таймкоды, заметки и статус;
  - drag-and-drop файлов между сегментами;
  - быстрый preview прямо в браузере;
  - пометки: подходит, сомнительно, заменить, нужен скриншот, нужен фрагмент;
  - история решений по сегменту.

- Smart linking:
  - автоопределение, к какому сегменту относится скачанный файл;
  - подсказки по названию раздела, URL, автору, тексту и времени добавления;
  - безопасное подтверждение перед автоматическим прикреплением;
  - поиск похожих файлов в медиатеке перед скачиванием нового.

- Source cards:
  - карточка источника с оригинальным URL, canonical URL, автором, датой, заголовком, описанием;
  - скриншот страницы источника как доказательство контекста;
  - сохранение текста страницы или выжимки для будущей проверки;
  - пометка надежности источника и причины выбора.

- Review mode:
  - список незакрытых сегментов;
  - список материалов без папки, без автора, без описания, без источника;
  - предупреждения о дублях и слабых fallback-скриншотах;
  - быстрый проход по выпуску перед монтажом.

## Phase 3 - Media Intelligence

Цель: инструмент должен понимать медиафайлы, а не просто хранить их.

- Video understanding:
  - автоизвлечение длительности, разрешения, FPS, codec, bitrate;
  - scene detection и keyframes;
  - быстрые thumbnails для перемотки;
  - поиск по визуально похожим кадрам;
  - распознавание вертикального/горизонтального формата и safety crop.

- Audio and speech:
  - автоматическая транскрибация видео;
  - поиск по произнесенным словам;
  - детектирование тишины, громких мест, музыки, аплодисментов;
  - подсказки для удачных таймкодов цитат.

- OCR:
  - распознавание текста в скриншотах, мемах, новостных карточках и титрах;
  - поиск по OCR в медиатеке;
  - предупреждение, если текст на изображении обрезан или плохо читается.

- Quality scoring:
  - автоматический выбор лучшего дубля;
  - флаги: low resolution, watermarked, silent, too short, black frames, corrupted;
  - рекомендация перекачать из другого источника;
  - сравнение файлов по фактическим параметрам, а не по имени.

## Phase 4 - Research And Discovery

Цель: UContent должен не только принимать ссылки, но и помогать искать материал.

- Research inbox:
  - единая лента из RSS, Telegram-каналов, поисковых запросов, YouTube, X/Twitter, TikTok;
  - сохраненные поисковые темы;
  - дедупликация новостей между источниками;
  - группировка по сюжетам.

- Story graph:
  - связь людей, компаний, мест, событий и источников;
  - история развития сюжета по времени;
  - источники за и против;
  - быстрый экспорт фактуры в сценарий.

- Watchlists:
  - отслеживание каналов, блогеров, ведомств, брендов, политиков, компаний;
  - уведомления о всплесках упоминаний;
  - автоматический сбор медиа по заданным темам;
  - черный список мусорных источников и повторов.

- Evidence pack:
  - по каждому спорному тезису хранить ссылку, скриншот, цитату, дату доступа;
  - экспорт пакета доказательств для фактчекинга;
  - отметка, какие источники уже использовались в выпуске.

## Phase 5 - Montage Handoff

Цель: монтажер должен получать не папку хаоса, а готовый пакет решений.

- Timeline export:
  - XML/EDL/FCPXML export с сегментами, файлами, таймкодами и комментариями;
  - стабильные имена файлов;
  - проверка, что все referenced media существуют;
  - one-click export package.

- Video cutter:
  - web UI для точной нарезки;
  - маркеры keep/cut;
  - экспорт отдельных клипов и монтажного листа;
  - быстрый Telegram flow для вырезания фрагмента без открытия полноценного редактора.

- Remotion integration:
  - генерация повторяемых графических элементов;
  - шаблоны цитат, заголовков, хронологий, карточек источников;
  - batch render для выпусковых вставок;
  - preview в браузере и экспорт в монтажный пакет.

- Asset standards:
  - автоматическое приведение имен, папок и форматов;
  - контроль aspect ratio;
  - предупреждения о плохом качестве до передачи в монтаж;
  - manifest выпуска: что, откуда, зачем и где используется.

## Phase 6 - Production Command Center

Цель: видеть состояние выпуска целиком.

- Dashboard:
  - статус всех сегментов;
  - сколько материалов найдено, скачано, прикреплено, проверено;
  - проблемные места: нет медиа, слабый источник, нужен монтаж, нужен скрин;
  - очередь задач на сегодня.

- Job system:
  - персистентная очередь фоновых задач;
  - retry policy;
  - отмена задач;
  - история download/render/cut/screenshot jobs;
  - понятные логи без лишнего шума.

- Notifications:
  - Telegram-уведомления о завершении тяжелых задач;
  - предупреждения о неудачных загрузках;
  - ежедневный digest состояния выпуска;
  - кнопки quick action из уведомления.

- Roles:
  - автор, редактор, монтажер, ресерчер;
  - приватные заметки и публичные комментарии;
  - назначение сегментов;
  - audit trail действий.

## Phase 7 - Archive And Memory

Цель: каждый выпуск усиливает будущие выпуски.

- Project archive:
  - завершенный выпуск сохраняется как самодостаточный пакет;
  - все источники, медиа, решения, таймкоды и экспортные файлы доступны позже;
  - быстрый поиск по прошлым выпускам.

- Reuse intelligence:
  - найти, где уже использовался этот источник или файл;
  - предупреждение о повторном использовании одного и того же видео;
  - подбор старых материалов по теме;
  - библиотека постоянных персонажей, компаний, мемов, мест.

- Knowledge base:
  - заметки по источникам и надежности;
  - справки по recurring topics;
  - сохраненные формулировки и контекст;
  - интеграция с Notion/Docs без потери локальной копии.

## Phase 8 - World-Class Polish

Цель: инструмент должен ощущаться профессиональным продуктом, а не внутренним скриптом.

- UI:
  - быстрый command palette;
  - keyboard shortcuts;
  - плотные таблицы и списки без визуального мусора;
  - responsive режим для телефона;
  - темная и светлая темы;
  - быстрый preview без скачков layout.

- Reliability:
  - crash-safe writes;
  - transactional moves/renames;
  - background migration system;
  - healthcheck для всех внешних инструментов;
  - backup/restore локальных данных.

- Observability:
  - human-readable logs;
  - debug bundle для проблемной загрузки;
  - метрики по времени загрузки, размеру, ошибкам, источникам;
  - страница system status.

- Onboarding:
  - setup wizard;
  - проверка `.env`;
  - тестовая загрузка;
  - sample project;
  - документация по типовым сценариям.

## Open Questions

- Что считать главным интерфейсом: Telegram, web UI или гибрид?
- Нужна ли многопользовательская работа, или достаточно локального single-user режима?
- Какой монтажный пакет должен быть первым классом: Premiere, Final Cut, DaVinci или neutral XML?
- Какие источники обязательны для надежной поддержки в первую очередь: TikTok, X/Twitter, Instagram, YouTube, Telegram, VK?
- Нужен ли встроенный LLM-слой для summaries, OCR cleanup, source clustering и подсказок по сценариям?
- Как хранить большие архивы: только локально, NAS, внешний диск, S3-compatible storage?

## Definition Of Done For New Features

- Работает в Docker и локально, если функция относится к runtime.
- Не ломает UTF-8 и русские тексты.
- Не теряет исходные файлы при ошибке.
- Пишет понятную ошибку пользователю.
- Обновляет `media-index.json`, если меняет медиа.
- Имеет хотя бы один smoke test или проверяемый ручной сценарий.
- Документирует новый workflow в README или отдельном документе.
